# El Galeón de Alcorcón: website

Website of **El Galeón de Alcorcón**, a *casa de comidas* (traditional Spanish cooking) at C. Milán, 2, 28922 Alcorcón (Madrid): **https://www.elgaleondealcorcon.com**.

- Spanish is the main language (no URL prefix); English is a faithful translation under `/en`.
- **Next.js 15** (App Router) + **next-intl 4** + **Tailwind CSS 3**, deployed on **Cloudflare Workers** through OpenNext. Every page is prerendered and served from the OpenNext cache.
- The site sets **no cookies** and collects no data, as its privacy policy says. Keep it that way (see [Privacy](#privacy-no-cookies)).

Rules for anyone changing the code: [CONTRIBUTING.md](CONTRIBUTING.md).

## Pages and URLs

| Page | Spanish | English | In Google |
|---|---|---|---|
| Home | `/` | `/en` | yes (the only indexed page) |
| Aviso legal | `/aviso-legal` | `/en/legal-notice` | no (`noindex`) |
| Política de privacidad | `/privacidad` | `/en/privacy` | no (`noindex`) |
| Any other URL | 404 page in Spanish | 404 page in English (`/en/...`) | status 404 |

- The Spanish URLs are exactly those of the previous site, so they keep their rankings.
- `/home` (a duplicate home page on the previous site) redirects permanently to `/`.
- No redirect by browser language: everyone lands on the URL they asked for, and the **ES · EN** switcher in the header changes language (on phones the header shows the other language only, and the menu lists both).

## Commands

```bash
npm ci                           # install (Node 22, see .node-version)
npm run dev                      # dev server on http://localhost:3000
npm run typecheck && npm run lint
npm run check:messages           # messages/es.json and en.json have the same keys
npm run build && npm start       # production build + server on :3000
npm run seo:check -- http://localhost:3000   # SEO smoke test (local or live URL)
npm run preview                  # build for Cloudflare and run on the Workers runtime
npm run deploy                   # build + deploy from your machine (normally Workers Builds does it)
```

CI (`.github/workflows/ci.yml`) runs typecheck, lint, check:messages, build and seo:check on every push to `main` and every pull request.

## Where things live

| What | Where |
|---|---|
| **Facts**: phone, email, address, opening hours, TheFork / carta / Instagram / Maps links, legal entity | `lib/site.ts` (one source for the page and the JSON-LD) |
| **Texts**, in both languages, including meta titles and descriptions | `messages/es.json`, `messages/en.json` |
| URLs per language, list of pages | `i18n/routing.ts` (`pathnames`) |
| Indexed pages (sitemap) | `INDEXED_PATHS` in `lib/site.ts` |
| Title, description, canonical, hreflang, Open Graph | `lib/seo.ts` → `pageMetadata()` |
| schema.org JSON-LD (Organization, WebSite, Restaurant) | `lib/structuredData.ts` |
| Photos (WebP, several widths) | `public/images/`, generated by `scripts/images/photos.py` from `scripts/images/originals/` |
| Icons, link-preview image, logo | `app/icon.png`, `app/apple-icon.png`, `app/favicon.ico`, `public/icons/`, `public/og-default.jpg`, `public/logo.png`, generated by `scripts/images/brand.py` |
| Colours (with measured contrast) / fonts | `lib/theme.ts` / `app/fonts.ts` |
| Design system: labels, buttons, framed photos, kitchen gallery, mobile menu, long-form pages, motion | `app/globals.css` |
| Redirects, security headers | `next.config.ts` (+ `public/_headers` for static files) |
| 404 handling | `middleware.ts` → `app/[locale]/not-found-page` |

## Common changes

**Opening hours, phone, address.** Edit `lib/site.ts`. The hero, the "Horario y contacto" section, the mobile menu, the JSON-LD and the street in the home page's meta description (`{street}` in `messages/*.json`) all follow. Change the Google Business Profile the same day, so Google sees the same facts everywhere.

**A text.** Edit it in **both** `messages/es.json` and `messages/en.json`, then run `npm run check:messages`.

**A photo.**
1. Put the original in `scripts/images/originals/`.
2. Add or change its line in `PHOTOS` in `scripts/images/photos.py`: crop, grade, widths. Dishes use the shared 4:3 crop and grade.
3. Run it: `python3 -I scripts/images/photos.py` (needs Pillow and NumPy). It rewrites `public/images/` and `lib/images.json`. File names stay the same, and `public/_headers` lets browsers cache photos for a week, so a replaced photo can take up to a week to reach returning visitors.
4. Add the alt text and caption to `home.photos.<name>` in both message files.
5. A photo can never be displayed wider than its largest exported width (the original's width): wider looks blurry.
6. A dish for the kitchen gallery: add its name to `KITCHEN_PHOTOS` in `lib/images.ts` (the caption numbers follow the order). Every dish shares the 4:3 crop, so the grid needs no per-photo sizes; it shows three per row on desktop, two on tablets and one on phones, so a multiple of six keeps every row full.

**Icons and link-preview image.** `python3 -I scripts/images/brand.py <CormorantGaramond-600.ttf>`. The script's header explains how to download the font.

**Display font.** Cormorant Garamond is served from `app/_fonts/`, not from `next/font/google`: its upright "á" puts the accent over the previous letter ("Milán", "Página"), so `scripts/fonts/patch-cormorant.py` moves that one accent and copies the italic unchanged. The script's header has the exact source package and command. Upgrading the font means re-running it (it refuses an unexpected font version).

**A new page.**
1. Add its URLs to `pathnames` in `i18n/routing.ts`: Spanish path as the key, `{ es, en }` as the value. **A page missing there returns 404**: the middleware treats every unlisted URL as unknown.
2. Create `app/[locale]/<spanish-path>/page.tsx` with `generateMetadata` returning `pageMetadata({ locale, path, title, description })`. Copy `app/[locale]/privacidad/page.tsx` as a starting point.
3. Add its texts, including `metaTitle` and `metaDescription`, to both message files.
4. Indexable: add its path to `INDEXED_PATHS`. Otherwise pass `noindex: true`.
5. Link to it from the header or footer with `Link` from `@/i18n/navigation`.
6. If it replaces an old URL, add a permanent redirect in `next.config.ts`.

## Deploy (Cloudflare Workers Builds)

Full guide: [docs/DEPLOY-CLOUDFLARE.md](docs/DEPLOY-CLOUDFLARE.md). In short:

1. Cloudflare dashboard → **Workers & Pages** → **Create** → **Import a repository** → this repo.
2. Build command `npx opennextjs-cloudflare build`, deploy command `npx opennextjs-cloudflare deploy`, production branch `main`.
   - The Worker must be named **`elgaleondealcorcon`**, as in `wrangler.jsonc`.
3. Every push to `main` deploys. Other branches build as previews with `robots.txt: Disallow: /` and `noindex`, so they never compete with the real site in Google.
4. Check the Worker URL before touching DNS:
   ```bash
   npm run seo:check -- https://elgaleondealcorcon.<account>.workers.dev
   curl -sI https://elgaleondealcorcon.<account>.workers.dev/ | grep -i x-opennext-cache   # HIT
   ```

## Switching the domain from the old host

The current site runs on another host at the same domain. The switch keeps every URL that Google knows, so rankings carry over. Follow **[docs/MIGRATION.md](docs/MIGRATION.md)**, which includes this site's URL map. The main steps:

1. Before the switch: check which host Google indexes (`site:elgaleondealcorcon.com`); `SITE_URL` uses `www`. Export the old DNS records, especially MX (email) and the TXT records (Google Search Console verification).
2. Move DNS to Cloudflare while still pointing at the old host, so there is no downtime ([DEPLOY-CLOUDFLARE.md §2](docs/DEPLOY-CLOUDFLARE.md#2-dns-move-the-domain-to-cloudflare)).
3. Attach `www.elgaleondealcorcon.com` to the Worker as a custom domain, and redirect the apex to `www` with a 301 Redirect Rule ([§3](docs/DEPLOY-CLOUDFLARE.md#3-point-the-domain-at-the-worker)).
4. Run `npm run seo:check -- https://www.elgaleondealcorcon.com`. It also checks that `http://` and the non-www host each redirect in one hop. Then submit the sitemap in Search Console.
5. Keep the old host for 1–2 weeks as a rollback path.

## Privacy: no cookies

The privacy policy (`/privacidad`) states that the site collects no personal data and uses no cookies. The code keeps that true:

- next-intl's `NEXT_LOCALE` cookie is off (`localeCookie: false` in `i18n/routing.ts`);
- fonts are self-hosted by `next/font` (no request to Google from the visitor's browser);
- there is no analytics, embedded map or other third-party script.

Adding any of these means updating the privacy policy first, and possibly a cookie banner.

## Open TODOs

- **Legal data:** the owner has to confirm the company data in the aviso legal. Search the code for `TODO(cliente)`; the data is the `legal` object in `lib/site.ts`. It was copied verbatim from the previous site, but the phone, email and address there do not match the restaurant's and may come from another project.
- **Vector logo:** only a 442 px wide PNG exists (`scripts/images/originals/logo.png`). An SVG would be sharper in the header and footer and in the link-preview image.
- **High-resolution dish photos:** the chuletón, alcachofas and brownie originals are 545 px wide (exported at 484 px), so the gallery's columns are capped at 340 px (`.gallery` in `app/globals.css`) to keep them sharp on high-density phones and tablets. Larger originals would allow lifting the cap.
- **Next.js 16:** `npm audit` reports the postcss copy bundled inside Next 15 (high) and Next itself (moderate, because of it). Next only runs postcss at build time on this project's own CSS, so nothing reaches it from visitors; the only fix is Next 16.4, a major upgrade. Do it as its own task: `@opennextjs/cloudflare` 1.20.9 or later supports it (check `npm view @opennextjs/cloudflare peerDependencies`), `next lint` must be replaced by the ESLint CLI (package.json, CI, CONTRIBUTING.md), and the full checks must pass again, including the 404 and `x-opennext-cache: HIT` checks on the Workers runtime (the 404 depends on `middleware.ts`).

## Known limitation

Calling `notFound()` while a page renders returns status 404, but Next.js 15 sends an empty error shell (`<html id="__next_error__">`) as the server HTML and fills it in the browser. React error boundaries do not run during server rendering. That is why unknown URLs never reach `notFound()`: the middleware rewrites them to the prerendered 404 page with status 404, which works with `next start` and on Cloudflare Workers. `seo:check` fails if a 404 regresses to the shell. A future page that needs `notFound()` (for example for an unknown slug) has the same limitation unless the middleware rejects the slug first.
